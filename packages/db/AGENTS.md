# Database Package Rules

- This package owns the Drizzle schema, migrations, and `createDb()`. Only `packages/api` queries it. The web app creates the one pool in `apps/web/src/lib/server/db.ts` and hands it to Better Auth and the API. This package never reads env vars at runtime.
- Change tables in `src/schema/` and export them from `src/schema/index.ts`. Then run `bun run db:generate`, read the generated SQL in `migrations/`, and commit it with the schema change. Apply it with `bun run db:migrate`.
- Never edit a migration that has been committed; generate a new one instead. Don't use `drizzle-kit push`.
- CI applies migrations to production after a merge to `main`, while the new code deploys. Keep each migration expand-only: add tables and columns before code depends on them, and drop them only after no deployed code reads them.
- `src/schema/auth.ts` is generated by Better Auth; see `packages/api/AGENTS.md` before changing it.
- `scripts/seed.ts` seeds local databases after every `db:migrate`. Keep it safe to run repeatedly.
